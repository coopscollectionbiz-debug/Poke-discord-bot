# Bot Expansion Compatibility — Gen 6–9

Read-only code audit of `coopscollectionbiz-debug/Poke-discord-bot` at `feature/release-c-achievements` (`33b797a2`: master `440f9c73` with Release B inventory and the Release C achievements). File references are relative to the repository root.

**Bottom line:** expanding the catalogue is **not** "add sprite URLs". Adding a species to `pokemonData.json` immediately puts it into most spawn pools, and the bot **will throw during battles** for any species missing from `battleData.json`. Fairy typing, regions, achievements and several hard-coded 649 limits also need deliberate changes. Player data needs **no migration**: inventories are keyed by national dex id, and 650–1025 do not collide with anything.

---

## 1. How the catalogue works today

| Concern | Where | Notes |
|---|---|---|
| Species catalogue | `pokemonData.json` (root) **and** `public/pokemonData.json` (byte-identical copy served to the dashboard) | 649 entries keyed `"1"…"649"`: `{id, name, tier, region, types[], flavor, evolvesTo[], evolvesFrom[]}`. No generation field, no forms. Both files must change together |
| Loaders | `utils/pokemonDataCache.js` (reads `public/pokemonData.json`), `utils/pokemonCache.js`, `utils/dataLoader.js`, `progression/achievements.js:26` (reads `public/pokemonData.json` directly) | `getAllPokemon()` feeds every pool |
| Enabled generations | Gen 1–5 only, enforced **only** by what is in `pokemonData.json`, plus `RECRUIT_MAX_DEX = 649` in `commands/recruit.js:152` | There is no "enabled" flag |
| Dex ids / forms | Plain national dex number as the string key. Forms are not represented. `public/sprites/pokemon/normal/` holds 24 PokéAPI form GIFs (10001–10024, Unown letters, Deoxys and others) that no code path uses | Forms would need a new key scheme. Out of scope for phase 1 |
| Rarity | `tier` field (common/uncommon/rare/epic/legendary/mythic), hand-assigned: 166/152/164/98/48/21 | Every new species needs a tier |
| Types | PokéAPI type ids 1–17. **No Fairy (18) anywhere in the data** (Clefairy is `Normal`) | See §3 |
| Battle data | `battleData.json`, generated by `tools/generate-battle-data.mjs` from `@pkmn/dex` **Gen 5** (`g5`), 17-type chart, 649 species | See §4 |

## 2. Sprites and delivery

- **Files:** `public/sprites/pokemon/{normal,shiny}/{id}.gif` (775/774 files), `…/{normal,shiny}/female/` (96 each, not referenced by code), and grayscale variants in `…/grayscale/` and `…/normal|shiny/grayscale/` (774 each; the dashboard uses them for not-owned cards). All are PokéAPI `black-white/animated` GIFs (verified by hash). They are committed to Git.
- **Serving:** Express serves `public/` (`bot_final.js:~497` sets `image/gif`). Discord embeds use absolute URLs built from `spriteconfig.js`: `BASE = process.env.RENDER_EXTERNAL_URL || 'https://poke-discord-bot-2.onrender.com'`. `fly.toml` does **not** set `RENDER_EXTERNAL_URL`, so either it is a Fly secret or embeds still point at the old Render host. **Verify before any sprite rollout** (read-only: `flyctl secrets list` shows names only). If embeds resolve to Render, new sprites deployed on Fly will not appear in Discord.
- **`.gif` is hard-coded in at least 15 call sites:** `bot_final.js:1030,1060,1428`, `services/gameplay.js:156,356`, `utils/broadcastReward.js:97`, `commands/{daily.js:209-214, inspectpokemon.js:84, pokedex.js:158, quest.js:87, recruit.js:196, shop.js:258, showteam.js:99, trainercard.js:154-162}`, `utils/trainerCardCanvas.js:215-218`, `public/dashboard/dashboard-script.js:432-436,1142,1171,1207`, `public/picker-pokemon/script.js:606,939,988,1174`, `public/dashboard/script.js` (legacy paths).
  → **Static-only species (class C) should be imported as single-frame GIFs**, not PNGs. That keeps every path working with zero code change. `utils/battle/render.js:loadSprite` decodes GIF only (omggif) and silently renders a tile **without** a sprite if the file is missing or not a GIF.
- **Trainer card canvas** (`utils/trainerCardCanvas.js:108`) tries `.png` before `.gif`. That is harmless.
- **Grayscale:** new species need grayscale GIFs in both grayscale folders, or the dashboard shows broken images for unowned cards. These can be generated from the colour files (the existing ones look like straight desaturation; confirm with one diff).
- **Canvas size:** existing GIFs are cropped to the sprite (Pikachu 50×46). Some Showdown `gen5ani` files keep a 96×96 canvas. Trim transparent borders at import so thumbnails and battle tiles line up.
- **Disk/repo cost:** about 12 MiB for 220 animated fronts, similar for shiny, plus grayscale. That is comparable to the existing set.
- **External dependency risk:** none today, because everything is self-hosted. Keep it that way (see the licensing doc §4 for the notice/credit precondition).

## 3. Types — Fairy is a blocker

- `pokemonData.json` uses type ids 1–17. `utils/battle/data.js:12` `TYPE_ID_TO_NAME` stops at 17 (Dark). `tools/generate-battle-data.mjs` hard-codes 17 types and Gen 5. `public/sprites/types/` has icons `1.png`–`17.png` only.
- `commands/pokedex.js:31-70` **already** maps 18 → fairy ✨, and `public/picker-pokemon/index.html:134` already has a Fairy filter. So parts of the UI expect Fairy.
- 42 of the 376 Gen 6–9 species are part-Fairy (Sylveon, the Flabébé line, Tapus, Zacian, Tinkatink line, and others). They cannot be represented without type 18.
- **Legacy retyping decision.** Under Gen 6+ rules, 22 existing species change type: Clefairy/Clefable/Cleffa, Togepi/Togetic/Togekiss, Snubbull/Granbull → Fairy. Jigglypuff/Wigglytuff/Igglybuff/Azurill → Normal/Fairy. Mr. Mime/Mime Jr./Ralts/Kirlia/Gardevoir → Psychic/Fairy. Marill/Azumarill → Water/Fairy. Mawile → Steel/Fairy. Cottonee/Whimsicott → Grass/Fairy. Retyping them **changes established gameplay**: battle matchups, the Gen 6 Steel nerf to the type chart, and `col_type_*` achievement progress (players lose Normal/Psychic counts). Unlocked achievements are kept, because `user.ach` records unlocks and state metrics never revoke. **Owner decision required:** (a) keep Gen 5 typing for #1–649 and use Fairy only for new species (inconsistent, but no change for existing players), or (b) move everything to Gen 9 typing as an announced balance change.
- Adding id 18 to `TYPE_ID_TO_NAME` automatically creates a new achievement, `col_type_fairy` ("Own 15 different Fairy-type Pokémon"), because `catalog/achievements.js:70` iterates the map. That needs a `CATALOG_REVISION` bump (§6).

## 4. Battles — hard blocker

- `utils/battle/data.js:getSpecies(id)` returns `data.species[id]`. `sim.js:buildMon`, `moveset.js:autoMoveset`, `power.js`, `rewards.js` and `commands/inspectpokemon.js:22` then read `species.baseStats` / `species.levelMoves` **with no guard**. One Gen 6+ Pokémon on a team, or a `/inspectpokemon` call on one, would throw.
- `battleData.json` must be regenerated to cover every enabled species before any of them can be caught. Options: generate Gen 6–9 species from `@pkmn` Gen 9 data while keeping the Gen 5 move pool and chart (smaller change), or move the whole sim to Gen 9 data (moves, Fairy chart). `tests/battleData.test.js:24` asserts exactly 649 species. The README's balance test (`battleBalance`, 24,000 simulated battles) must be re-run, because new base stats (e.g. Gen 9 legendaries) shift the Underdog/Elo tuning.

## 5. Encounters, spawns, shiny odds

- **Every pool except `/recruit` reads all of `pokemonData`:** `utils/weightedRandom.js:selectRandomPokemonForUser` (daily, chat catches), `services/gameplay.js:336` (dashboard tier pools), `commands/shop.js:242`, `commands/quest.js`. Adding a row makes the species catchable everywhere at once. `/recruit` is the only one capped (`RECRUIT_MAX_DEX`, asserted in `tests/assets.test.js:109`).
  → Phase gating needs **one** explicit allow-list (e.g. an `enabled`/`releasePhase` field, or a separate `pokemonData.gen6-9.json` merged at load), applied in `getAllPokemon()`, so pools, recruit, dashboard and achievements all agree.
- **Tier-first weighting** (`POKEMON_RARITY_WEIGHTS`): the odds of rolling a tier do not change, but the odds per species inside a tier fall. Adding all 376 roughly halves each existing species' chance. Legendary/mythic are hit hardest: 69 today, +36 legendary +10 mythical among new species. Players chasing a specific old legendary will notice. Consider adding new species in phases, or a per-release "featured" weight.
- **Shiny:** `shinyOdds.js` is species-agnostic, so it needs no change. For class B/C species a shiny roll must still display something distinct. Every species has a verified static shiny, so the shiny path never has to fall back to the normal sprite. But a shiny of a B species will be static while its normal is animated. Decide whether that is acceptable or whether such species should be excluded (Option A in the rollout doc).

## 6. Achievements (Release C)

- `catalog/achievements.js:40` hard-codes `REGIONS = { Kanto: 151, Johto: 100, Hoenn: 135, Sinnoh: 107, Unova: 156 }`, "verified against pokemonData.json". `tests/regions.test.js:64` asserts the five names. `CONTEXT.md:52` defines regions as those five.
- New regions (Kalos 72, Alola 88, Galar 89 + Hisui 7 (#899–905), Paldea 120 incl. Kitakami/Blueberry) create `col_region_*_half/full` achievements, a badge/title each, all retro-evaluated.
  - **Partial rollouts break "region complete".** If only 48 Kalos species are enabled, "Kalos Pokédex Complete" means 48. When phase 2 adds the rest, the target moves, and players who unlocked it keep the unlock (by design) against a now-incomplete Pokédex. **Recommendation:** add a region's achievements only once the whole region is enabled, or name them by phase.
  - Region assignment needs decisions for Hisui species (Wyrdeer, Kleavor, Ursaluna, Basculegion, Sneasler, Overqwil, Enamorus) and for the Kitakami/Blueberry DLC species, which are all national-dex Gen 8/9.
- `uniqueSpecies` milestones (25/100/250/500) are unaffected, though they become easier. `tier:legendary`/`tier:mythic` are unaffected. `type:*` counts change if legacy species are retyped (§3).
- Any catalogue change must bump `CATALOG_REVISION` so the retro evaluator (`progression/achievements.js:207`) re-runs once per player.
- Rewards are still `pending_approval` (D-07), so there is no economic exposure from new region achievements until rewards are enabled.

## 7. Evolution

- `services/gameplay.js:180` only allows targets listed in `evolvesTo` (exploit fix, PR #50). **18 existing species gain Gen 6+ evolutions:** Eevee→Sylveon, Zigzagoon→Obstagoon\*, Meowth→Perrserker\*, Corsola→Cursola\*, Farfetch'd→Sirfetch'd\*, Mr. Mime→Mr. Rime\*, Yamask→Runerigus\*, Stantler→Wyrdeer, Scyther→Kleavor, Ursaring→Ursaluna, Basculin→Basculegion\*, Sneasel→Sneasler\*, Qwilfish→Overqwil\*, Primeape→Annihilape, Wooper→Clodsire\*, Girafarig→Farigiraf, Dunsparce→Dudunsparce, Bisharp→Kingambit.
  \* In the games these come from a **regional form** (Galarian Zigzagoon, Hisuian Sneasel, Paldean Wooper, and so on), which the bot does not model. Decide whether the base form may evolve, or whether these stay unavailable until forms exist.
- Editing `evolvesTo` on existing species is a visible gameplay change for current owners. Evolution costs depend on stage and tier, so new species need stage data as well.
- Other evolution conditions (trade, friendship, level, items) are flattened to Evolution Stones today, and new species can follow the same rule.

## 8. Inventory, collection, trading, saved data

- `user.pokemon` is `{ [dexId]: { normal, shiny } }`. Release B normalisation (`bot_final.js:~270`) keeps unknown ids and only deletes empty entries. **Adding 650–1025 needs no migration**, and existing records are untouched.
- **Rollback risk:** if a species is caught and then removed from `pokemonData.json`, the record keeps an id that the dashboard, `/pokedex` and the achievement metrics cannot resolve. Never remove enabled species; disable spawning instead (the allow-list in §5).
- `commands/gift.js` and bulk donate key by id, so they need no change. Trading (Release F) is not built yet. The journal/reconciler open item stands regardless.
- Pokédex completion (`CONTEXT.md:118`) counts per species, not per variant, so it needs no change. Dashboard region headers derive regions from data (`public/picker-pokemon/regions.js`), so new regions appear automatically, in id order.
- Forms (Megas, regional variants, etc.) would need a new id scheme (e.g. the PokéAPI 10xxx ids already used in the CSV), plus a separate sprite key and UI. Nothing in the current data model supports them.

## 9. Discord rendering

- Animated GIF thumbnails/images work as they do today. The largest Gen 6–9 front is 201 KiB, well within embed limits.
- Single-frame GIFs (static species) render as static images.
- Names with special characters: Flabébé, Type: Null, Mr. Rime, Sirfetch'd, Jangmo-o/Hakamo-o/Kommo-o, Chien-Pao, Wo-Chien, Ting-Lu, Chi-Yu, Porygon-Z. `/pokedex` matches with `name.toLowerCase() ===` (`commands/pokedex.js:130`), so users must type the accent and punctuation exactly. Add accent/punctuation-insensitive matching.
- Starter selection (`commands/trainercard.js:203-207`) lists 5 regions. New starters are optional.
