# Battles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add auto-simulated Pokémon battles between players — Open and Wager battles, Levels/EXP, Battle rating, and Level display — per the locked design.

**Architecture:** A pure, seeded Gen 5 battle engine (`utils/battle/`) runs on a committed `battleData.json` generated once from Pokémon Showdown data. Player progress lives in new server-authoritative user fields (`training`, `battle`, `pendingWager`). Discord commands lock both players, run and persist the whole battle, then replay ~4 rendered frames.

**Tech Stack:** Node 22 ESM, discord.js 14.24.2, @napi-rs/canvas, Express 5; dev-only `@pkmn/dex@0.10.12` + `@pkmn/data@0.10.12` (already installed, exact-pinned).

**Spec:** `docs/superpowers/specs/2026-11-02-battles-design.md` (glossary: `CONTEXT.md`)

## Global Constraints

- Use **CONTEXT.md terms** in code, copy, and comments: Team, Level, EXP, Catch level, Stage, Tier, Variant, Open battle, Wager battle, Challenger, Defender, Stake, All-in, Battle rating, Battle cap, Power rating, Underdog, Underdog surge. Never "rank" for Battle rating, never "XP".
- American English in all copy and comments.
- No new runtime dependencies. `@pkmn/*` are devDependencies used only by `tools/generate-battle-data.mjs`; nothing in `utils/`, `commands/`, or `bot_final.js` imports them.
- Data era is Gen 5: 649 species, 17 types (no Fairy), `5L` level-up learnsets.
- Battle cap: 10 battles started per UTC day (same `YYYY-MM-DD` UTC key as `commands/daily.js:35-36`), max 3 per opponent per day.
- Wager: hold window 15 minutes; min Stake 1 CC; no maximum; no house cut.
- Elo: start 1000, K 32.
- Playback: 4 frame updates, 2.5 s apart, after an initial frame.
- `training`, `battle`, `pendingWager` are server-authoritative: never add them to the `/api/updateUser` allowlist (`bot_final.js:1469`).
- Every number in `utils/battle/tuning.js` is a tunable starting point; Task 7's Monte Carlo test is what validates the battle ones.
- Tests: plain `node` scripts named `tests/*.test.js` (picked up by `run-tests.js`), using the shared harness from Task 1. Exit code 1 on any failure.
- Commit after each task (confirmed). The spec and plan under `docs/superpowers/` are committed with Task 1.
- Ponytail: smallest complete change; no options, wrappers, or "for later" code. Future move management needs no code now — `training` records being objects (`{ exp }`) is what leaves room for an optional moveset.

## Review Focus

1. **Restart while a wager is pending** — the Stake is refunded exactly once, even if the old collector or a late button click fires afterward. → Task 11 test `refund is idempotent by nonce`.
2. **Double click / concurrent battles** — Defender double-clicks Accept, or the Challenger fires two `/battle`s at once → exactly one battle and one Stake movement. → Task 11 test `second accept with same nonce fails`; Task 9 holds both locks in sorted order.
3. **Team member no longer owned** — a Team slot whose variant count dropped to 0 is skipped; a Team with no owned members counts as no Team. → Task 6 test `unowned team slots are dropped`.
4. **Level cap** — EXP past Lv 100 stops at exactly `expForLevel(100)`; no "Lv 100 → 101" or phantom learned moves. → Task 3 test `addExp clamps at level 100`.
5. **UTC day rollover mid-wager** — a wager offered 23:55 UTC and accepted 00:05 is counted against the new day, and caps are checked at accept time. → Task 6 test `caps use the day of the battle, not the offer`.

### Task 2: Battle engine core

**Files:**
- Create: `utils/battle/{tuning,rng,data,stats,moveset,sim}.js`, `tests/battleSim.test.js`

**Interfaces:**
- Produces `tuning.js` (named exports, starting values):
  `IV = 15`, `LEVEL_CAP = 100`, `DAMAGE_ROLL_MIN = 0.80` (Gen 5 is 0.85), `CRIT_CHANCE = 1/12`, `HIGH_CRIT_CHANCE = 1/8` (moves with `critRatio ≥ 2`; Gen 5 is 1/16 and 1/8), `CRIT_MULT = 2`, `MOVE_RANDOM_CHANCE = 0.1`, `TURN_CAP = 300` (Task 7 resets it to ≥ 3× measured p99), `SURGE = { minRatio: 1.25, perRatio: 0.05, maxChance: 0.2, statMult: 1.6 }`, `CATCH_RANGES = { 1:{min:2,max:15,tailMax:35}, 2:{min:16,max:32,tailMax:50}, 3:{min:32,max:45,tailMax:65}, legendary:{min:40,max:55,tailMax:75} }`, `CATCH_SKEW = 2`, `CATCH_TAIL_CHANCE = 0.03`, `DUPLICATE_LEVEL_SHARE = 0.5`, `BST_YIELD_SCALE = 0.035`, `TRAINER_BATTLE_MULT = 1.5`, `WIN_EXP_MULT = 1.5`, `ELO = {start:1000,k:32}`, `CAPS = {perDay:10,perOpponent:3}`, `WAGER = {minStake:1,windowMs:15*60*1000}`, `PLAYBACK = {frames:4,delayMs:2500}`.
- Produces `rng.js`: `createRng(seed: number) → { next(): number /*[0,1)*/, int(n: number): number /*0..n-1*/ }` (mulberry32).
- Produces `data.js`: `TYPE_ID_TO_NAME`, `getSpecies(id: number)`, `getMove(moveId: string)`, `effectiveness(moveType: string, defenderTypes: string[]) → number`, `fallbackMoveFor(types: string[]) → string` (uses `types[0]`).
- Produces `stats.js`: `computeStats(baseStats, level) → {hp,atk,def,spa,spd,spe}` — Gen 5: HP `floor((2B+IV)·L/100)+L+10`, others `floor((2B+IV)·L/100)+5`, EV 0.
- Produces `moveset.js`: `autoMoveset(speciesId, level) → string[]` — the last 4 distinct battle-usable moves learned at or below `level`; `[fallbackMoveFor(types)]` if none. `movesLearned(speciesId, fromLevel, toLevel) → string[]` — ids in `autoMoveset(to)` but not in `autoMoveset(from)`.
- Produces `sim.js`:
  ```
  simulateBattle({ sides: [Side, Side], seed: number, surge: { side: 0|1, statMult: number } | null })
    → { winner: 0|1, turns: number, endedBy: "knockout"|"turnCap",
        snapshots: number[][][],   // snapshots[t][side][slot] = HP fraction 0..1; t=0 is the start
        knockouts: { turn, side, slot, bySide, bySlot }[] }
  Side = { members: { speciesId: number, variant: "normal"|"shiny", level: number }[] }  // 1–6 members
  ```
  Rules: each side's first non-fainted member is active. Each turn both actives choose a move (with `MOVE_RANDOM_CHANCE` a uniform pick from the moveset, otherwise the highest expected damage: power × STAB × effectiveness × (A/D) × accuracy). Order: Speed, then coin flip. An action is skipped if the actor fainted or the target fainted earlier that turn. Accuracy: `accuracy === true` never misses, otherwise hit if `rng.next() < accuracy/100`. Damage: `floor(floor(floor(2L/5+2)·P·A/D)/50)+2`, × STAB 1.5 × effectiveness × crit (`CRIT_MULT`; `CRIT_CHANCE`, or `HIGH_CRIT_CHANCE` when `critRatio ≥ 2`) × roll `DAMAGE_ROLL_MIN..1`, floor, min 1 unless effectiveness is 0. Physical uses atk/def, Special spa/spd. **Shedinja (`292`):** max HP is always 1, and Wonder Guard means it takes damage only when effectiveness > 1 (comment: the one ability modeled, per spec). Surge multiplies atk/def/spa/spd/spe of every member on `surge.side` by `statMult`. At `TURN_CAP` the side with the higher total remaining HP fraction wins (exact tie → side 1, the Defender). The result is a pure function of the inputs.

- Produces (`utils/training.js`):
  - `trainingKey(id, variant) → "6:normal"`
  - `expForLevel(level) → number` = `level <= 1 ? 0 : level ** 3` (Medium Fast).
  - `levelForExp(exp) → number` in 1..100: start from `Math.floor(Math.cbrt(exp))`, then step down while `L³ > exp` and up while `(L+1)³ ≤ exp` (`Math.cbrt` isn't exact on every perfect cube), clamp to 1..100.
  - `stageOf(speciesId) → 1|2|3`; `catchBand(speciesId) → 1|2|3|"legendary"` (`"legendary"` when Tier is legendary/mythic and Stage is 1).
  - `floorLevel(speciesId) → number` = `CATCH_RANGES[band].min`.
  - `rollCatchLevel(speciesId, rand = Math.random) → number`: with probability `CATCH_TAIL_CHANCE`, uniform in `(max, tailMax]`; otherwise `min + floor((max-min+1) · u^CATCH_SKEW)`.
  - `getTraining(user, id, variant) → { exp, level }` (no record → `exp = expForLevel(floorLevel(id))`; never writes).
  - `addExp(user, id, variant, amount) → { fromLevel, toLevel }` (creates the record from the default; clamps at `expForLevel(100)`).
  - `grantCatch(user, speciesId, variant, rand = Math.random) → { level, isNew, expGained }`: increments `user.pokemon[id][variant]` (creating `{normal:0,shiny:0}`), then: no `training` record → set `exp = expForLevel(rollCatchLevel(id, rand))`, `isNew = true`; record exists (any count, even 0) → `expGained = floor((expForLevel(L+1) - expForLevel(L)) · DUPLICATE_LEVEL_SHARE)` at the current Level `L` (0 at Lv 100) via `addExp`. No roll on the duplicate path.
  - `carryLevel(user, from: {id, variant}, to: {id, variant}) → void`: target `exp = max(getTraining(to).exp, getTraining(from).exp)`, written as a record. Floor default applies (spec: user's call).
  - `levelsForUser(user) → { [key]: number }` (Level for every owned variant, count > 0).
