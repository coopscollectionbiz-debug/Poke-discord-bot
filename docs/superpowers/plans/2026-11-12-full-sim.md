# Full simulation and Battle plans: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every fight runs on Pokémon Showdown's engine with a plan-steered AI, behind `FULL_SIM_ENABLED`, while the switch-off path stays byte-for-byte today's.

**Architecture:** A synchronous Showdown adapter (`utils/battle/showdown/`) exposes `simulateFull()` with `simulateBattle()`'s inputs and a superset of its result. It runs on a sim worker pool shaped like `utils/render/renderPool.js`. A plan-weighted AI (`utils/battle/ai/`) chooses every move. Full-sim data lives in its own generated file, chosen by the switch.

**Tech Stack:** Node 22 ESM, `@pkmn/sim` 0.10.12 (exact pin), `worker_threads`, `zlib` (built-in), the repo's own test runner (`npm run test:safe`, files `tests/*.test.js`).

**Spec:** `docs/superpowers/specs/2026-11-12-full-sim-design.md`

## Global Constraints

- `@pkmn/sim` pinned to exactly `0.10.12` in `dependencies`. No other new dependency (no `@smogon/calc`).
- Showdown format id: `gen9customgame@@@!teampreview`.
- Sets: IVs all 15 (`tuning.js` `IV`), EVs all 0, nature Hardy.
- Randomness under the full sim: damage roll integer 80..100 %, crit 1/12 at stage 0, high-crit 1/8, crit damage ×2 (`tuning.js` `DAMAGE_ROLL_MIN`, `CRIT_CHANCE`, `HIGH_CRIT_CHANCE`, `CRIT_MULT`).
- Turn cap 300 (`TURN_CAP`). At the cap, more total HP fraction wins; an exact tie goes to side 1 (the Defender).
- No clauses. No voluntary switches. Faint or switch-out move: lowest-slot healthy benched Pokémon. Drags stay Showdown-random.
- Switch off: `battleData.json`, `sim.js`, `effects.js` and every existing test behave exactly as on master.
- All new player-facing copy goes through `/unslop` before it's final. American English.
- Skill levels: Rookie slip 0.35, Solid slip 0.1 (`MOVE_RANDOM_CHANCE`), Expert = Solid + 1-turn lookahead over the top 3 candidates.

## Review Focus

1. A Team whose every member is fainted at the start of an Elite Four fight ends the fight at once (today's `outAtStart`), instead of hanging the driver. Test in Task 2.
2. A Pokémon with no usable move left (all PP out, Taunted with only status, Choice-locked into a disabled move) must still act: `choose()` false falls back to `choose('default')`, then Struggle. Test in Task 1.
3. A Mega slot that is no longer battle-ready, and a held item Showdown doesn't know (Lucky Egg), must fight as the base form with no item instead of throwing. Test in Task 2.
4. A picked Moveset move that the full-sim learnset no longer allows still appears in battle until edited, and a Team member migrated at cutover keeps the same 4 moves on the first full-sim fight. Test in Task 8.
5. Turning the switch off mid Elite Four run: the run finishes on the engine stamped at its start. Test in Task 5.

### Task 2: Sets, results and `simulateFull`

**Files:**
- Create: `utils/battle/showdown/sets.js`, `utils/battle/showdown/result.js`, `utils/battle/showdown/simulate.js`
- Test: `tests/fullSimResult.test.js`

**Interfaces:**
- Consumes: Task 1.
- Produces:
  - `memberSet(member, { slot, levelMult = 1, statMult = 1, ability }) => Set | null` (null for a fainted carry-over member). Species is `member.battleProfile?.showdownName ?? species name`. Level is `min(100, round(level × levelMult))`. Moves come from `memberMoves(member)`. Item comes from `showdownItem(id)`: catalog name, or `''` for ids Showdown doesn't know (Lucky Egg). `hp` is from `hpFraction`, `status` from `member.status`.
  - `simulateFull({ sides, seed, surge, ai }) => Result`. `ai` defaults to Solid with All-out attack for both sides.
  - `Result` = v1 fields `{ winner: 0|1, turns, endedBy: "knockout"|"turnCap", snapshots, knockouts: [{turn, side, slot, bySide, bySlot, cause}], log }` plus `v: 2`, `steps: Step[][]` (per turn), `raw: string[]`, `endStatus: [string[], string[]]` (status per slot at the end).
  - `Step` = `{ kind: "move", side, slot, target, move, missed?, crit?, eff? } | { kind: "hp", side, slot, hpAfter, from? } | { kind: "switch", side, slot, drag? } | { kind: "status", side, slot, status } | { kind: "faint", side, slot, cause } | { kind: "note", text }`.
  - `log` keeps the v1 per-hit event shape (`side, slot, targetSlot, move, damage, hpAfter, fainted, crit, eff, missed`) so stats pages keep working.

- [ ] Write failing tests:
  - `result has every v1 field`, and `knockouts[k].bySide === 1 - side` for each KO.
  - `KO credit`: a poison KO credits the foe on the field. A recoil self-KO credits the foe it hit.
  - `steps`: a battle with Stealth Rock and Toxic contains `hp` steps with `from` and a `status` step.
  - `fainted carry-over member is left out`, and `all fainted at start` returns `{ turns: 0, winner: other side }`.
  - `E4 carry`: a member with `hpFraction 0.5, status "psn"` starts at half HP, poisoned.
  - `Lucky Egg and a stale Mega fight without throwing`.
  - `Mega slot fights with profile stats` (Charizard-Mega-X attack equals the profile's).
- [ ] Implement `result.js` from `tools/spike-showdown/extract.mjs`. Snapshots are read per original slot after each turn, plus a final push when the battle ends. At the turn cap, compute the HP tiebreak.
- [ ] Run the tests. Expect PASS.

### Task 4: AI (estimator, plans, skill levels)

**Files:**
- Create: `catalog/battlePlans.js`, `utils/battle/ai/estimate.js`, `utils/battle/ai/choose.js`, `utils/battle/ai/abilities.js`
- Test: `tests/battleAi.test.js`, `tests/battlePlans.test.js`

**Interfaces:**
- Produces:
  - `BATTLE_PLANS`: ids `allout`, `setup`, `status`, `hazards`, `weather`, `speed`, each `{ id, name, keyMoves: string[], blurb }`. `DEFAULT_PLAN = "allout"`.
  - `estimateDamage(b, attacker, defender, moveId) => number` (expected HP fraction, no random draws).
  - `makeChooser({ plan, skill: "rookie"|"solid"|"expert", rng }) => (req, b, side) => string`.
  - `pickAbility(speciesId, plan) => string` (regular abilities only; a Mega uses its profile's).
  - `planReadiness(members, plan) => { ready: boolean, helpers: number, missing: string[] }`.
- Plan bonuses: `speed` scores Trick Room when the foe is faster and Trick Room is down (Tailwind when own side is faster); `setup` scores a boost when the foe's best estimate against it is under 0.5; `status` scores a major status move on a foe with no status; `hazards` scores an unset hazard or screen while ≥ 3 foes remain; `weather` scores setting the weather that matches the most own-side abilities or STAB types, when it isn't up.

- [ ] Write failing tests, one scenario each (fixed seed, 1v1 or 2v2 sets):
  - All-out picks the highest-estimate move.
  - Speed control: a slower Bronzong uses Trick Room on turn 1; with Trick Room up it attacks.
  - Set up: Scizor with Swords Dance boosts turn 1 against a weak foe and attacks against a strong one.
  - Status: Thunder Wave on an unstatused foe, never on a paralyzed one.
  - Hazards: Stealth Rock on turn 1 versus 3+ foes, never twice.
  - Weather: Kingdra (Swift Swim) sets rain.
  - Rookie differs from Solid on at least 20% of turns over 200 seeded decisions.
  - Expert beats Solid more than 50% over 200 seat-swapped battles.
  - `pickAbility`: Kingdra on `weather` gets Swift Swim; hidden abilities are never returned.
  - `planReadiness`: `speed` on a Team without Trick Room or Tailwind is `{ ready: false }`.
  - `estimateDamage` draws nothing from the battle's random generator (the PRNG seed is unchanged after 100 calls).
- [ ] Implement. Then measure: extend `tools/spike-showdown/p5_perf.mjs` with a `solid` and an `expert` mode and record the figures in the spec's Measured table.
